# HU-19: Compresión client-side de fotos de vehículos

**Como** usuario interno de la concesionaria (vendedor o administrador),
**quiero** que las fotos que selecciono se compriman en el navegador antes de ser enviadas al servidor,
**para** poder subir múltiples fotos sin recibir errores de payload demasiado grande.

## Descripción

Al cargar muchas fotos de vehículos (tanto en la creación/edición de un vehículo como en las fotos de vehículos en parte de pago dentro de una operación), el servidor de Vercel rechaza la request con un error HTTP 413 `FUNCTION_PAYLOAD_TOO_LARGE`, ya que el límite de payload para funciones serverless es de 4.5MB.

Actualmente la compresión de imágenes ocurre en el servidor (usando Sharp), pero el payload raw ya superó el límite antes de que el servidor pueda procesarlo. La solución es mover la compresión al navegador: generar la versión full (1280px WebP) y el thumbnail (400px WebP) client-side usando la Canvas API, y eliminar el procesamiento server-side redundante.

## Criterios de aceptación

- [ ] Al seleccionar fotos en el formulario de creación de vehículo, cada imagen se comprime client-side antes de ser almacenada en el estado.
- [ ] Al seleccionar fotos en el formulario de edición de vehículo, ídem.
- [ ] Al seleccionar fotos de vehículo en parte de pago en una operación, ídem.
- [ ] Se generan dos versiones client-side por foto: full (máx 1280px, WebP) y thumbnail (máx 400px, WebP).
- [ ] Ambas versiones se envían al servidor en el FormData.
- [ ] El servidor almacena directamente los bytes recibidos sin volver a comprimir.
- [ ] Crear un vehículo con 10 fotos pesadas no produce error 413.
- [ ] Las fotos se visualizan correctamente en el detalle del vehículo tras la carga.

## Notas técnicas

- La compresión se implementa con la Canvas API nativa del navegador (sin librerías externas).
- El servidor deja de usar `processVehiclePhoto` de `src/lib/imageProcessor.ts` para los flujos afectados.
- El FormData cambia: se agrega un campo `fotosThumb_${index}` paralelo a cada `fotos` para enviar el thumbnail.
- Para las fotos de trade-in en operaciones, se usa el mismo esquema: `vehiculosUsadoFotosThumb_${vehicleIndex}_${photoIndex}`.
- La función `processVehiclePhoto` en `imageProcessor.ts` queda sin uso tras completar todas las porciones (puede eliminarse en una limpieza posterior).
