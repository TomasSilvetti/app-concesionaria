# HU-20: Tablero Kanban para seguimiento de pendientes

**Como** miembro del equipo de la concesionaria,
**quiero** gestionar los autos pendientes de clientes en un tablero kanban con columnas personalizables y tarjetas arrastrables,
**para** hacer un seguimiento visual y colaborativo del estado de cada pedido de cliente.

## Descripción

El módulo de Pendientes se rediseña como un tablero kanban. Cada columna representa un estado del proceso (ej: "Buscando", "En negociación", "Listo para entregar") y puede ser creada, renombrada, reordenada o eliminada por cualquier usuario. Dentro de cada columna se crean tarjetas que representan un auto que un cliente quiere conseguir. Las tarjetas muestran el título y el usuario que las creó, y al hacer clic se abre un modal con el detalle completo, incluyendo un cuerpo de texto con soporte para checklists. Las tarjetas pueden moverse entre columnas mediante drag & drop.

## Criterios de aceptación

- [ ] El tablero muestra al menos 3 columnas por defecto y permite agregar columnas adicionales con nombre personalizado.
- [ ] Cada tarjeta muestra en la vista de columna: título y nombre del usuario que la creó.
- [ ] Al hacer clic en una tarjeta se abre un modal con: título, cuerpo completo (con checklists renderizados), usuario creador, y botones de editar y eliminar.
- [ ] El cuerpo de una tarjeta soporta ítems de checklist, con un atajo para insertar `[ ]` rápidamente desde el editor.
- [ ] Las tarjetas pueden arrastrarse entre columnas mediante drag & drop; el cambio se persiste automáticamente.
- [ ] Las columnas pueden reordenarse mediante drag & drop.
- [ ] Al eliminar una columna que contiene tarjetas, el sistema muestra una advertencia y requiere confirmación del usuario.
- [ ] Al eliminar una tarjeta, el sistema pide confirmación antes de borrar.
- [ ] El nombre del usuario creador se asocia automáticamente a la tarjeta al momento de crearla; no es editable.

## Flujos

### Flujo principal — Mover una tarjeta entre columnas

1. El usuario ve el tablero con sus columnas y tarjetas.
2. Agarra una tarjeta con drag & drop y la arrastra a otra columna.
3. Suelta la tarjeta en la columna destino.
4. El sistema actualiza la posición de la tarjeta y persiste el cambio en la base de datos.

### Flujo principal — Crear una tarjeta

1. El usuario hace clic en el botón "Agregar" dentro de una columna.
2. Se abre un formulario/modal con campos de título y cuerpo.
3. El usuario redacta el cuerpo; puede usar el atajo para insertar ítems de checklist (`[ ]`).
4. El usuario guarda la tarjeta.
5. La tarjeta aparece en la columna con el título y el nombre del usuario creador.

### Flujo principal — Ver detalle de una tarjeta

1. El usuario hace clic sobre una tarjeta en el tablero.
2. Se abre un modal con el título, el cuerpo (con checklists renderizados e interactuables), el usuario creador, y opciones para editar y eliminar.
3. El usuario cierra el modal o navega a otra tarjeta.

### Flujo alternativo 1 — Agregar una nueva columna

1. El usuario hace clic en "Agregar columna".
2. Ingresa el nombre de la nueva columna y confirma.
3. La columna aparece al final del tablero vacía y lista para recibir tarjetas.

### Flujo alternativo 2 — Eliminar columna con tarjetas

1. El usuario intenta eliminar una columna que contiene tarjetas.
2. El sistema muestra una advertencia: "Esta columna tiene X tarjetas. Si la eliminás, se borrarán todas."
3. El usuario confirma o cancela.
4. Si confirma, la columna y todas sus tarjetas se eliminan permanentemente.

### Flujo alternativo 3 — Eliminar una tarjeta

1. El usuario abre el modal de detalle de una tarjeta y hace clic en "Eliminar".
2. El sistema pide confirmación.
3. Si confirma, la tarjeta se elimina y el modal se cierra.

### Flujo alternativo 4 — Editar una tarjeta

1. Desde el modal de detalle, el usuario hace clic en "Editar".
2. El título y el cuerpo se vuelven editables.
3. El usuario guarda los cambios; el modal se actualiza con el nuevo contenido.

## Notas técnicas

⚠️ **Base de datos:** Esta historia requiere persistir columnas (nombre, orden) y tarjetas (título, cuerpo, columna asociada, orden dentro de la columna, usuario creador). También debe persistirse el estado de los ítems de checklist dentro del cuerpo de cada tarjeta. El equipo deberá verificar si la estructura de base de datos actual soporta estas entidades o si es necesario crear nuevas tablas/modelos.
